Lecture Topic: Relational Keys - Super Key, Candidate Key, and Primary Key

In relational databases, tuples must be distinguishable from one another. No two tuples in a valid relation state can have the identical values for all attributes. We enforce this uniqueness using keys:
1. Super Key: A set of one or more attributes that, taken collectively, allows us to identify uniquely a tuple in the relation. If K is a super key, then any superset of K is also a super key.
2. Candidate Key: A minimal super key. That is, a candidate key is a set of attributes that uniquely identifies a tuple, such that no proper subset has the uniqueness property. A relation may have multiple candidate keys.
3. Primary Key: A candidate key chosen by the database designer as the principal means of identifying tuples within the relation. The primary key must never contain null values; this rule is formalised as the Entity Integrity Constraint.
4. Foreign Key: An attribute or set of attributes in a relation that refers to the primary key of another relation. The Referential Integrity Constraint requires that any foreign key value must either match an existing primary key value in the referenced table or be null.

Lecture Topic: Third Normal Form (3NF) and Eliminating Transitive Dependencies

Even if a relation is in 2NF, it may still suffer from update anomalies due to transitive dependencies.
Definition of Transitive Dependency: A functional dependency X -> Z is a transitive dependency if there exists a set of attributes Y such that X -> Y and Y -> Z hold, where Y does not determine X, and Z is not a subset of X or Y.
Definition of Third Normal Form (3NF):
A relation schema R is in 3NF if, whenever a non-trivial functional dependency X -> A holds on R, either:
1. X is a super key of R, OR
2. A is a prime attribute of R (A is part of some candidate key).
Alternative definition: A relation is in 3NF if it is in 2NF and no non-prime attribute is transitively dependent on any candidate key.
Example: Consider Employee(Emp_ID, Dept_ID, Dept_Name).
Emp_ID -> Dept_ID, and Dept_ID -> Dept_Name.
Here Emp_ID -> Dept_Name is transitive through Dept_ID. Since Dept_Name is non-prime and Dept_ID is not a super key, this violates 3NF. We decompose into: Emp(Emp_ID, Dept_ID) and Dept(Dept_ID, Dept_Name).
